# What_if 本地推演

## 三阶段完整子树（2026-10-03）

新故事使用 `three-stage-v2`：发现可能性 → 合理深化 → 自然收束。每个任务一次返回完整子树，整体验证通过后一次挂到原树并保存；第二、三阶段只续接上一阶段的开放叶节点，全部当前阶段任务完成后才进入下一阶段。第三阶段未确定的状态保留为开放结尾，不再自动安排第四阶段。旧故事不自动重建，仍沿用旧调度。

| 模式 | 第一次：新增层数 / 子树叶端路径 | 第二次：每条开放叶新增层数 / 叶端路径 | 第三次：每条开放叶新增层数 / 叶端路径 |
| --- | --- | --- | --- |
| 轻度 | 2–3 / 4–5 | 2 / 2–3 | 2–3 / 1–2 |
| 正常 | 3 / 6–8 | 3 / 3–4 | 2–4 / 1–2 |
| 深度 | 3–4 / 9–11 | 4 / 3–4 | 3–4 / 1–2 |

路径数指整棵返回子树的叶节点数，不是每个父节点的子节点数。范围下限是内容建议，上限由服务端校验；有依据的稳定状态可提前结束，不强迫凑数。每个父节点仍最多 2 / 3 / 5 个直接子节点。约 15 / 30 / 45–55 条最终线路仅是流程设计参考，不进入提示词、不构成全树配额，也不保证实际数量。新故事总深度上限为 8 / 10 / 12，起点不计层。

新版第一阶段聚焦直接回应与近期变化，第二阶段观察选择落实和实际磨合，第三阶段完成长期收束。初步缓和、愿意尝试并不自动等于稳定结局；已经稳定的状态仍可提前结束，不为增加路线编造悬念。主要路径的设计跨度仍为 6–8 / 8–10 / 10–12 层。实际路线分布尚未用真实模型重新测量，数量仅为预期。

已有 `three-stage-v1` 故事继续使用原局部叶端范围：轻度 4–6 / 2–3 / 1–2、正常 6–10 / 3–5 / 1–2、深度 10–14 / 4–5 / 1–2；保留其提示词与最高 56 个节点的局部预算。刷新或续算不会把旧故事改成新版本，也不重新生成已完成故事。

每次传入事实基线、当前状态和完整祖先路径，使用独立阶段任务说明和共同五字段契约，不提供完整情节树样例。Qwen 的每次请求使用 JSON Schema、32768 输出 token 预算、180 秒超时。有效子树仅叶端路线超额时，第二次调用只选择保留的现有路线 ID，程序保留完整祖先链后再次校验，不重写整棵树；可行时每个第一层方向至少保留一条。筛选结果格式不正确时会再请求一次筛选，最多三次模型调用；仍失败则不静默删除路线、不保存超额树。筛选和重试都计入免费调用额度。结构验证期间最多接受 96 个候选节点，最终保存仍遵守原有局部预算。其他格式、截断或超时最多再尝试一次同样规模的完整子树；仍失败就暂停，不降为单层，不写入半棵树。故事脉络整理的格式错误也最多重试一次。额度和访问错误不自动重试。模式局部节点上限由最大叶数 × 最大层数推导，新版最高 44；预算不是必须用满。

每日免费新故事 2 次及单故事每日 80 次模型请求上限不变，重试也计调用。深度模式可能触及调用额度，此时保存当前任务，隔日继续同一故事；新故事次数不会重复扣除。

实现入口：`web/generation-flow.mjs`（局部预算与任务顺序）、`backend/prompt.mjs`（三阶段提示词）、`backend/server.mjs`（验证与重试）、`backend/trial-store.mjs`（版本、进度与额度）。`generationStage` 是节点保存元数据，不是模型输出字段。老 API 不传 `generationStrategy` 仍采用旧算法；当前输入页创建故事时明确传新版本。

### 备份与回滚

改造前完整代码、资源、测试和私有数据快照位于本机同级目录 `../What_if-backups/20261002-202008-before-three-stage/`，含 SHA-256 清单与 `RESTORE.md`。`private/` 内含配置及故事数据，不可发布。浏览器首次读到旧故事时会另存 `what-if-before-three-stage`；新建故事会删除这个快照和其他旧故事备份。

回滚前停止服务，另存当前代码与故事数据；再恢复备份的 `web/`、`backend/`、`scripts/`、`test/` 和 `package.json`。不要直接覆盖当前 `.what-if-trial.json`，以免抹掉新故事及额度记录。完整旧版不能识别三阶段进度：回滚后的新版本故事仅保留归档，不应继续计算；需要恢复三阶段版本后续算。具体步骤见备份中的 `RESTORE.md`。

以下两阶段描述保留为旧故事兼容说明；较早视觉说明亦保留为历史记录。

## 匿名访客试用（本机验证版）

运行 `npm start` 时，页面会在浏览器 `localStorage` 保存一枚随机访客凭证；普通刷新、关闭标签页或重启浏览器后仍使用同一凭证。服务端只保存其 SHA-256 摘要，不把站点模型密钥交给前端。试用规则是每个访客每天最多**新建 2 个免费故事**，全站每天最多新建 50 个免费故事；同一故事的整理、分批推演、失败重试和刷新后继续都不重复占用新故事次数。试用用完、继续个人故事缺少配置，以及右上角菜单的手动配置，统一打开「配置我的 API」弹窗。用户填写 HTTPS 接口根地址（Base URL）、模型名称和 API Key，支持兼容 Chat Completions 的模型服务，不限定 Qwen；原生其他协议暂不支持。配置只存在当前浏览器会话的 `sessionStorage`，不写入故事文件；个人故事的整理和生成均使用该地址、模型和 Key，不占站点免费额度。免费故事始终使用站点配置；本站未配置模型时也可通过个人配置新建故事。旧会话仅保存 Key 的用户需补全地址和模型。上线时网页和 API 必须使用 HTTPS。服务端另设每日站点模型调用预算，达到预算后免费故事可隔天继续。

访客额度、当前故事编号和无正文的分支结构保存在项目根目录的 `.what-if-trial.json`（已加入 `.gitignore`，文件权限仅当前用户可读写）。故事正文、整理结果和生成结果只保存在当前浏览器的 `localStorage`；刷新、关闭标签页再打开仍能恢复，清除站点数据或换设备后不能恢复。新建故事会删除同一浏览器中的上一故事及其备份，服务端也删除上一故事的结构记录；主动清空也会删除服务端记录。启动本机服务时会清除旧版文件中保存的正文。删除浏览器站点数据或使用新的无痕窗口会得到新访客凭证，因此这只能限制普通使用，**无法识别真实个人或阻止刻意换身份**；全站预算负责限制总费用。本地 JSON 文件只适合单进程验证。上线阿里云函数计算前，必须改为跨实例共享的持久数据库与原子配额更新，并在网关做限流；当前 `start:fc` 未配置持久存储时会拒绝启动。

> 当前产品方向、已实现功能、历史方案、公开发布架构与下一步计划，请先阅读 [PROJECT_STATUS.md](./PROJECT_STATUS.md)。本 README 的部分湖面视觉描述属于较早版本。

在本机运行 `npm start`，打开 `http://127.0.0.1:3000`。写下想改变的“如果”和当时的完整故事，点击「开始推演」。长故事先经 `/prepare` 整理为反事实、已知事实、时间线、明确的心情或动机以及未知问题；可在页面展开「查看整理后的故事脉络」。之后 `/generate` 自动完成所有分支，无需逐个选择节点。很短且没有背景的假设由程序直接整理，不额外调用模型。

新故事从平视的晨雾湖面开始。提交后输入纸页淡出、收拢成纸球落入湖中，视角转为俯视；落点的涟漪成为故事起点，后续事件以较小的涟漪沿水纹展开。已经保存的故事刷新后直接进入地图，不会重播转场；系统开启「减少动态效果」时也会直接切换地图。湖面背景是静态素材，输入、节点与详情卡仍是可交互的网页元素。

故事地图从左向右发散：绿色表示发展节点，蓝色表示正在查看，金色表示自然结局。按住空白处拖动，或在 Mac 触控板上双指滑动，可自由平移画布；双指捏合以指针位置为中心缩放。底部也提供放大、缩小、全图、起点、最新节点和逐个浏览结局的控件。节点标题在缩放时始终保留；缩小到总览时，节点直径不会低于约 21 像素，标题也会得到字号补偿。悬停节点出现涟漪；点击节点会打开从起点到该节点的所有详情窗，以紧凑的间距为后续支线腾出空间并点亮来路。详情卡用「层级/同级序号」标记，例如第 3 层的第 1 个分支是 `3/1`。展开原始故事时，详情卡等速淡出；收起后淡入，打开的路径不会丢失。同一层只保留一个详情窗，切换支线时保留共同祖先的窗口；关闭某层或按 Escape 会收起该层及下层。移出视口的详情保持打开状态，平移回来后重新显示。新增节点时保持当前视角。

输入面板可选三种推演模式：轻度最多 8 轮、每个节点最多 2 个子分支；正常最多 12 轮、最多 3 个子分支；深度最多 15 轮、最多 5 个子分支。分支数和轮数都是上限，只有具备独立因果依据时才分叉，稳定结局可以提前结束。新故事直接采用所选模式；已有故事切换模式后，需要点击「按此模式重新推演」，仅切换选项不会调用模型或替换当前树。旧故事继续按原来保存的轮数显示和续算。

推演在目标轮次的三分之二处切换阶段：轻度第 6 轮、正常第 8 轮、深度第 10 轮。前段沿用轻度／正常最多 3 层、深度最多 2 层的短批次，且不跨越分界；后段按树中的顺序逐条处理分支，优先一次生成该分支的剩余层数。前段单批上限仍为 24／32 个节点、90 秒；后段最多 96 个节点，完整请求预算为 32768 输出 token、180 秒。超时、截断或格式不合格时，后端修正或缩为最多 2 层、再缩为 1 层续接；额度不足时直接暂停。每次成功后保存进度，手动暂停或失败后仍可继续，免费试用的每日额度保持不变。每条开放叶子保存简短的 `memory`；下一批只发送整理后的故事脉络、当前状态和最近节点，旧版没有 `memory` 的节点沿用原路径。不会因为提示词更新自动重建已完成的旧树。

## 本机模型配置

模型配置存放在项目根目录的 `.env.local`，包含 `AI_BASE_URL`、`AI_MODEL` 和 `AI_API_KEY`。该文件已被 `.gitignore` 排除，文件权限为当前用户可读写；不要把它上传到仓库或分享给别人。网页不会显示或保存密钥，模型请求由本机服务发出。更换配置后重启 `npm start`。

本机需要 Node.js 20.6 或更新版本。若 3000 端口已被其他程序占用，先结束旧的 `npm start` 进程。长故事整理会增加一次模型调用；后续批量生成与精简分支状态可以减少重复输入，但每个节点的输出仍消耗 Token，实际费用是否下降取决于故事规模与模型输出。可点击「本次完成后暂停」，当前请求完成后保存进度。

试用模式的故事正文只保存在浏览器，刷新后从本地恢复；服务端仅核对额度和分支结构。顶部输入面板可展开或收起；已有故事时输入只读，修改需要新建故事。点击「重新推演」会新建一次故事并永久替换旧故事：有剩余免费额度时优先使用免费额度，否则使用已配置的个人 API Key。中断时可点击「继续推演」；刷新不会重复扣除一次新故事。站点密钥不保存在浏览器中，个人密钥仅保留在当前浏览器会话。

## 无费用演示和检查

运行 `npm run demo`，打开 `http://localhost:8000`。该演示使用模拟模型，能看到故事整理、多层生成、精简状态续接和自然结局，不调用真实接口。运行 `npm test` 可检查两阶段请求、分支状态与树形返回。

## 将来迁移

网页位于 `web/`，模型请求和提示词在 `backend/`。本机入口 `scripts/local.mjs` 将服务绑定到 `127.0.0.1`。以后迁移云函数时，需要重新设计面向公众的密钥管理、接口访问控制和费用限制；本机 `.env.local` 不应随部署包上传。
